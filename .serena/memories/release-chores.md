# Release chores

Fixed order: verify → README version history → CHANGELOG → release. Do not reorder; the CHANGELOG is generated from commits that are already in the tree.

## 1. Verify (repo root, pnpm installed)

- `pnpm run lint` — must be clean (eslint + the binding n8n node rules, see `mem:tech_stack`).
- `pnpm run build` — `n8n-node build`, writes `dist/`.
- `pnpm run typecheck` — `tsc --noEmit` through the local compiler.
- `pnpm exec prettier --check .` — must print "All files formatted correctly"; fix with `pnpm exec prettier --write .`. It only passes when the working tree holds LF; a Windows checkout (`core.autocrlf=true`, no `.gitattributes`) reports every CRLF file as unformatted although `git diff` is empty for those files.

## 2. README version history

- File `README.md`, section `## 📝 Version history`; the newest entry is the first `###` below the heading.
- Entry shape, mirroring the existing entries: `### vX.Y.Z`, one sentence naming the new resources and the new resource total, then a bullet list per new resource (`- **<Operation>** — <one-line effect>.`), then a closing sentence for non-resource changes.
- Compare against the last released version: `git describe --tags --abbrev=0` (tags are `vX.Y.Z`).
- Take operation names and effects from `nodes/Coolify/descriptions/<Resource>/<Resource>Description.ts` and the `## ⚙️ Operations` sections of `README.md`; never invent an operation.

## 3. CHANGELOG

- Tool: `auto-changelog` (the "Generated by auto-changelog" credit in `CHANGELOG.md`; `.release-it.json` runs `npx auto-changelog -p` in `afterBump`).
- Command: `npx auto-changelog --latest-version vX.Y.Z --commit-limit false`.
  - `--latest-version vX.Y.Z` names the unreleased commits with the new version and writes the `compare/v<prev>...v<new>` link. Use it while `package.json` still holds the old version: plain `-p` reads the version from `package.json`, so before the bump it labels the new commits with the **old** version and a self-comparing link (`compare/v0.1.4...v0.1.4`).
  - `--commit-limit false` keeps every commit of every release. The default limit is 3 and silently truncates each older release to 3 commits.
- The command **rewrites the whole file**. Keep only the new `#### [vX.Y.Z](.../compare/...)` block (inserted after the `Generated by ...` credit line) and leave every older release note byte-identical — older notes are incremental and are never regenerated. A full regeneration re-labels older releases, adds their `Release X.Y.Z` and chore commits, and adds `> <date>` lines that were not there before.
- Sanity check: `git diff -- CHANGELOG.md` shows insertions only, exactly one new section.

## 4. Release

- `pnpm run release:local` (release-it + `.release-it.json`): `beforeInit` runs `pnpm run lint && pnpm run build`, then it bumps `package.json`, regenerates the changelog in `afterBump`, commits, tags `v<version>` and pushes. `pnpm run release` is the CI entry point (`n8n-node release`).
- Branch must be `master`; release-it refuses a dirty working directory, a missing upstream or no new commits.
- CI (`publish.yml`) publishes to npm on `v*.*.*` tags, never from a local machine.
